# Purpose

This document defines the implementation strategy for the Employee Lifecycle Portal.

Every sprint should end with:

- Successful Build
- Successful Testing
- Git Commit
- GitHub Push
- Updated Documentation

Main branch must always remain deployable.

---

# Sprint Workflow

Every sprint follows this exact sequence.

1. Analyze current architecture
2. Identify required folders
3. Create folders
4. Create files
5. Replace complete files
6. Build
7. Resolve errors
8. Test
9. Commit
10. Push
11. Update documentation
